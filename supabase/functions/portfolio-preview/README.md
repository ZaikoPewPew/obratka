# Edge Function: `portfolio-preview`

Прокси/кэш перед [thum.io](https://www.thum.io/) для превью-скриншотов карточек портфолио на home. Закрывает пункт "thum.io без ключа — единая точка отказа" из плана устойчивости к наплыву.

## Зачем

У анонимного (без ключа) тира thum.io жёсткие лимиты запросов. Раньше клиент бил в `image.thum.io` напрямую на каждую карточку (`portfolioPreviewUrl` в `src/api/portfolios.js`), полагаясь только на встроенный `maxAge/24` у самого thum.io. При резком наплюве (сотни новых непрогретых превью одновременно) это даёт массовые 429 и битые карточки.

Функция:

1. Кэширует успешный скриншот в Storage-бакете `portfolio-previews` на **24 ч** (`CACHE_TTL_SEC`) — повторный просмотр той же карточки любым пользователем не бьёт thum.io заново.
2. При `429` от thum.io делает один retry с бэкоффом (~0.5–0.8 с).
3. Если retry не помог (429 повторно / таймаут / 5xx) — отдаёт последний закэшированный снимок, даже протухший (до 7 дней, `STALE_TTL_SEC`), вместо ошибки. Совсем без кэша — `204` (клиент уже умеет показывать `--empty` состояние на `error` у `<img>`, см. `home-screen/HomeScreen.js`).
4. Готова к платному ключу thum.io "из коробки": если он появится, достаточно задать secret `THUMIO_AUTH_KEY` — код трогать не надо (`auth/<key>/` сегмент подставляется автоматически).
5. Самоочищается — без `pg_cron` (в проекте не подключён) и без отдельной функции: с вероятностью `CLEANUP_PROBABILITY` (2% запросов) фоновый sweep (`EdgeRuntime.waitUntil`, не блокирует ответ) удаляет до `CLEANUP_BATCH_SIZE` самых старых по `updated_at` объектов, если их не трогали дольше `PURGE_AFTER_SEC` (30 дней). Любой реальный просмотр карточки обновляет `updated_at` через upsert, так что востребованные превью не удаляются — вычищаются только те, на чьи портфолио никто давно не смотрит (например, давно набравшие 3/3 и выпавшие из очереди). Без этого бакет рос бы бесконечно с числом когда-либо просмотренных URL.

## URL

```
${SUPABASE_URL}/functions/v1/portfolio-preview?url=<encoded portfolio url>
```

Вызывается напрямую из `<img src>` (`portfolioPreviewUrl` в `src/api/portfolios.js`) — без `Authorization`/`apikey` заголовков, поэтому `verify_jwt = false` в `supabase/config.toml` (функция публична и сама не хранит ничего чувствительного; сервисный ключ используется только внутри для записи в Storage).

## Storage

Бакет `portfolio-previews` — `public = true` (публичный GET через `/storage/v1/object/public/...` без RLS-политики), но **без** политик `INSERT/UPDATE/DELETE` для `anon`/`authenticated` — пишет только эта функция через `service_role` (bypass RLS). SQL: [`supabase/sql/portfolio_preview_cache.sql`](../../sql/portfolio_preview_cache.sql).

Путь объекта — `sha256(url).jpg`, без вложенных папок.

## Секреты (опционально)

```bash
supabase secrets set THUMIO_AUTH_KEY=<paid-thumio-auth-key>
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` подставляются платформой автоматически.

## Ограничения / осознанно не сделано

- Нет полноценного анти-abuse rate-limit по IP (нужна отдельная KV/таблица) — открытый (без ключа) вызов thum.io был и раньше доступен любому напрямую, эта функция не делает поверхность атаки принципиально шире, только добавляет кэш и надёжность.
- `parseSafeTargetUrl` — базовый SSRF-фильтр (http/https + блок явных локальных/служебных хостов), не исчерпывающий; реальный источник `url` — уже отрендеренная RLS-защищённая лента.
